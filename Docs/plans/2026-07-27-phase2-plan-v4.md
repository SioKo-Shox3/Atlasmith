**隔離モジュール規約(numpy専用規約の例外設計)【BL-9 反映】**:

1. 第三者 ML/GL ライブラリを import してよいのは **`render.py` と `sam2_masks.py` の2ファイルだけ**。
2. **隔離モジュールでも module 直下では import しない。** `_import_moderngl()` / `_import_sam2()` / `_import_torch()` ヘルパ**関数内**で import し、`ImportError` を行動可能なメッセージへ変換して `from e` で再送出する。
   - **WHY(テスト可能性)**: 依存が導入済みの環境でも「未導入時のエラー経路」を monkeypatch でテストできる。トップレベル `try/except ImportError` は導入済み環境で不到達コードになり、ゲートが張れない。
3. **`if TYPE_CHECKING:` ブロック内の import も「module 直下」として禁止する。**
   - **WHY**: 「実行時には走らないから安全」という判断を検査に持ち込むと抜け道になる。型注釈は `from __future__ import annotations`(既存全ファイルが採用 — 例 `src/atlasmith/types.py:7`)で文字列化されるため、文字列注釈+必要なら関数内 import で書ける。
4. `importlib.import_module(...)` / `__import__(...)` も同じ規約に服する(隔離モジュール外では禁止、隔離モジュール内では関数内のみ)。
5. `segmentation` 配下から trimesh / xatlas / PIL / `atlasmith.io` / `atlasmith.pack` / `atlasmith.bake` を import しない。

**機械的ゲート(§6 に数値化)**:
- (a) `sys.modules` 検査 **3本**: `import atlasmith` / `import atlasmith.segmentation` / `import atlasmith.segmentation.multiview` のいずれの後にも `torch`/`moderngl`/`sam2` が **0 件**。
- (b) AST 検査(**隔離モジュールも除外しない**): 検査対象 = `src/atlasmith/segmentation/**/*.py` + `src/atlasmith/{__init__,cli,types}.py`。`ast.walk` で全 `Import`/`ImportFrom`/`Call` を集め、**祖先に `FunctionDef`/`AsyncFunctionDef` を持たないもの**を「module 直下」と判定。禁止パッケージ(`torch`/`moderngl`/`sam2`/`trimesh`/`xatlas`/`PIL`)の module 直下 import が **0 件**。`importlib.import_module`/`__import__` の呼び出しも同基準。
  - 除外パッケージ: `src/atlasmith/io/`(trimesh/PIL 可)、`src/atlasmith/pack/`(xatlas 可)は検査対象外(既存規約どおり)。

**所有権/寿命/スレッド(`architecture.md:24-33` への追補)【BL-11 反映】**

`architecture.md:26-27` は「長寿命リソースを導入する際はここに生成/破棄の正規ルートを記録する」と要求している。Phase 2 で初めて該当するので、**Protocol に寿命操作を持たせる**:

```python
class RenderedView(NamedTuple):
    face_id:  np.ndarray   # (H, W) int32、-1 = 背景。row 0 = 画面上端
    color:    np.ndarray   # (H, W, 3) uint8、row 0 = 画面上端
    coverage: np.ndarray   # (H, W) bool、前景=True(色値から独立した被覆判定)

class MeshRenderer(Protocol):
    def __enter__(self) -> "MeshRenderer": ...
    def __exit__(self, exc_type, exc, tb) -> None: ...
    def render_view(self, camera: Camera) -> RenderedView: ...

class MaskProposer(Protocol):
    def propose(self, view: RenderedView) -> np.ndarray: ...   # (K, H, W) bool
    def close(self) -> None: ...
```

- **`_ModernglRenderer` の完全契約(Step 2-3 で確定 — 後続ステップが禁止パスで直せないため計画で先に固定)**:
  - 生成: `_ModernglRenderer(mesh: MeshData, *, image_size: int, shading: str, face_codes: np.ndarray | None = None)`。
  - `face_codes` は **internal・テスト専用**(既定 `np.arange(M, dtype=np.int64)`)。docstring に WHY を書く(BL-10 の sentinel ゲートに必要)。
  - `__enter__` で GL コンテキストと GPU リソースを生成、`__exit__` で **生成の逆順に** `release()`(fbo → texture/renderbuffer → vao → vbo → program → ctx)。例外経路でも必ず通す。
  - `__exit__` 後の `render_view` は `RuntimeError`。同一インスタンスの `__enter__` 再入も `RuntimeError`。
  - `render_view` の戻り値は上記 `RenderedView`(dtype/shape/行順を docstring で固定)。
- **`MultiViewSegmenter` は context manager**:
  - `proposer` を**所有**し、`close()` / `__exit__` で `proposer.close()` を呼ぶ。
  - `renderer` は **`segment()` 呼び出しごとに `with` で生成・破棄**(メッシュ依存のため長寿命化しない)。
  - `make_sam2_segmenter(...)` の戻り値は `MultiViewSegmenter`(= context manager)。
  - **CLI は必ず `with` で囲む。**
  - **API 利用者**: `rebake(segmentation=backend)` に注入された backend を **`rebake` は閉じない**(所有権は呼び出し側)。`rebake` の docstring と `architecture.md` に明記。

- **スレッド**: 全段シングルスレッド(`architecture.md:29-33` 不変)。GL コンテキストも torch 推論も呼び出しスレッドに束縛。並列化は Phase 3 で技術選定を通す。
- `MeshData` は値渡し・引数非破壊(不変)。segmentation は新配列だけを返す。
- **IR**: `MeshData` にフィールドを追加しない(v2 §2.5 の決定を維持)。labels は関数引数で明示的に受け渡す。

#### 2.4.1 カメラ配置(`cameras.py`、numpy のみ)

- 中心 = `vertices` の AABB 中心、`R` = AABB 中心からの最大距離(外接球半径)。
- 視点方向 = **Fibonacci 球**(RNG 不使用・決定的):`z_i = 1 - (2i+1)/N`、`θ_i = π(1+√5)·i`。既定 `n_views = 24`。
- 投影: `projection ∈ {"perspective","orthographic"}`。既定は **spike(Step 2-1.5)の実測で確定**(§7 UNCERTAIN)。透視のとき `fov_deg = 30.0`、距離 `d = R / sin(fov/2) · 1.1`。正射影のとき half-extent = `R · 1.1`。
- up ベクトル: `[0,0,1]`、`|dot(dir, up)| > 0.99` のときのみ `[0,1,0]`(決定的分岐)。
- **near/far**: `near = d - R·1.2`(> 0 を保証)、`far = d + R·1.2`。**全頂点が視錐台内に収まる**ことを前提とし、そうでなければ `ValueError`(near クリッピングは扱わない — 独立オラクル(§2.4.2)の前提でもある)。
- 背面カリングは **無効化**(`ctx.disable(moderngl.CULL_FACE)`)。AI 生成メッシュは巻き順が不整合なことがあり、カリングすると面が消える。深度テストで最近接面が勝つだけでよい。
- **「全面が最低1視点から見える」ことは保証しない(正直な記述)**。代わりに **2種類の被覆率を分けて実測する【NB 反映】**:
  - `visible_ratio` = **face_id バッファに1視点でも現れた面**の割合。
  - `assigned_ratio` = **`view_segment >= 0` が1視点でもある面**の割合。
  - 警告の出し分け(原因別・誤誘導しない):
    - `visible_ratio < visible_warn`(既定 0.95)→「内部空洞の可能性。`--seg-views` を増やす/`--segmenter geometric`」。
    - `visible_ratio` は十分だが `assigned_ratio < assigned_warn`(既定 0.90)→「マスクが面を覆えていない。`points_per_side` / `image_size` を上げる」。
  - 未割当面のラベルは幾何プライアだけで決まる(§2.4.5 パス2)ため、**黙って壊れず幾何相当に劣化する**。

#### 2.4.2 面IDバッファ(`faceid.py` + `render.py`)— 逆投影の厳密化

**採用方式: 1回の描画で MRT(Multiple Render Targets)へ「色」と「面ID」を同時出力する。**

- 頂点バッファは **面ごとにアンロール**(3M 頂点)。属性: `in_position vec3` / `in_uv vec2` / `in_code vec3`(面IDのエンコード色)/ `in_normal vec3`。
  - **`in_code` と `in_normal` は VS/FS 双方で `flat` 修飾子必須。**【BL-10 反映】付けないと三角形内で補間され、面IDが壊れる。**専用ゲート**で「1面が覆う全画素のデコード値が同一」を検査する。
  - **WHY アンロール**: `gl_PrimitiveID` の「ジオメトリシェーダ無し時の値」というスペック隅に依存しない。M ≤ 数十万なら 3M 頂点のコストは無視できる。
- FBO 構成: `color0 = RGBA8(色)`、`color1 = RGBA8(面ID+被覆)`、`depth = depth renderbuffer`、**マルチサンプル無し(samples=0)**。
  - **WHY 1パス MRT**: 別パスだと深度の同点処理やドライバ都合で画素対応が食い違い得る。同一描画コールなら**構造的に**画素対応が保証される。
  - **WHY 整数テクスチャ(R32UI)ではなく RGBA8**: 整数アタッチメントは `glClearBufferuiv` が必要で moderngl の `Framebuffer.clear()`(float 経路)との相性が不確実。RGBA8 なら `clear()` で背景=0 が自明に定義でき、UNORM8 の往復はビット厳密。
- **GL 状態の明示【BL-10 反映】**:
  - `ctx.enable(moderngl.DEPTH_TEST)` / `ctx.disable(moderngl.CULL_FACE)` / **`ctx.disable(moderngl.BLEND)`**。
  - `FRAMEBUFFER_SRGB` は有効化しない。
  - **`GL_DITHER` は OpenGL 既定で有効**。固定小数点カラーバッファを厳密ID用途に使うので本来は無効化したいが、**moderngl の公開 API に無効化手段があるか未確認 → Step 2-3 probe (f) で確認する**。
    - 無効化できる場合は明示的に無効化する。
    - できない場合の扱い(裁定): **GPU 上の sentinel 面IDテスト(§6)を「ディザ不在の実証」として位置づける**。RGBA8 で 8bit → 8bit の書き込みはディザの対象にならない(色深度が減らない)ため実害は無い見込みだが、**それを推測で済ませずゲートで示す**。sentinel が1値でもずれたら停止し、R32UI 経路へ切替(Phase 3 送りを前倒し)。
- **24bit エンコード規約**(production とテストで共有する数値契約):
  - 送出値 `e = face_code + 1`(**0 は背景専用**)。既定 `face_code = face_index`。
  - `R = e & 0xFF`, `G = (e >> 8) & 0xFF`, `B = (e >> 16) & 0xFF`, **`A = 255`(前景マーカー)**。シェーダは `vec4(R/255.0, G/255.0, B/255.0, 1.0)` を出力。クリア値は `(0,0,0,0)`。
  - **デコード式(NEP 50 対応 — uint8 のまま演算しない)【NB 反映】**:
    ```
    rgb      = buf[..., :3].astype(np.int64)      # uint8 → int64 に明示昇格(NEP 50 で uint8 の 256 倍は OverflowError)
    e        = rgb[..., 0] + 256 * rgb[..., 1] + 65536 * rgb[..., 2]
    face_id  = (e - 1).astype(np.int32)           # e == 0 → -1
    coverage = buf[..., 3] == 255                 # 色値から独立した被覆判定【NB 反映】
    ```
  - **production の fail-loud 不変条件**: `coverage ⇔ (face_id >= 0)` が全画素で成立。違反は `ValueError`(ディザ/ブレンド事故の検出網)。
  - **上限**: `M <= 16_777_215`(= 2²⁴−1)。超過時は `ValueError`(実 M・上限・`--segmenter geometric`・将来の R32UI 経路をメッセージに明記)。**黙って上位ビットを捨てない。**
- 読み戻し: `fbo.read(attachment=..., components=4, dtype='f1')` → `np.frombuffer` → `(H,W,4) uint8`。
  - **`glReadPixels` の原点は左下**。`MeshData.maps` の V 規約は「row 0 = 画像上端 = V=0」(`architecture.md:73`)。**読み戻し後に必ず行方向を反転**する。
  - **V方向ゲートは 2 本課す【NB 反映】**: テクスチャ経路のゲート(2×2 既知テクスチャ)だけだと「アップロードの V 規約」と「読み戻しの行反転」が**両方逆でも緑になる**(`architecture.md:106-112` が記録する V1 残存リスクと同型)。**テクスチャを一切通さない独立ゲート**(既知カメラで +Y 側 facet の face_id が row < H/2 に現れる)を併せて課す。

#### 2.4.3 色画像(SAM2 への入力)【v4 で設計変更 — planner 発見の欠陥】

**v3 の「無ライティングの basecolor を既定」は、単色/無テクスチャのメッシュで平坦なシルエットしか出さず、SAM2 に内部の形状手がかりを一切与えない。** BL-5(c) が要求する「単色 fixture での ML ゲート」は、この既定のままでは原理的に成立しない。→ `shading` パラメータを導入する。

- `n_enc = normal_object * 0.5 + 0.5`(**面法線・オブジェクト空間**・`flat`・[0,1]³)。
  - **WHY オブジェクト空間**: ビュー空間法線だと同じ面が視点ごとに別色になり、視点間融合が壊れる。オブジェクト空間なら**視点非依存**。
- `shading` の3値(いずれも視点非依存 = 視点間一貫性を保つ):
  | 値 | 出力色 |
  |---|---|
  | `"texture"` | `basecolor(uv)` |
  | `"normal"` | `n_enc` |
  | `"texture_normal"` | `0.5 * basecolor(uv) + 0.5 * n_enc` |
- **テクスチャ無し(`mesh.uv is None` または `"basecolor" not in mesh.maps`)は常に `"normal"` に落ちる**。切替は `logging.info` で記録(黙らない)。
- **既定値は spike(Step 2-1.5)の実測で確定**(§7 UNCERTAIN-2)。planner 推奨は `"texture_normal"`(アルベドと形状の双方を渡し、かつ視点非依存)。
- sRGB 変換は行わない。`maps` は float32 [0,1] 線形扱い(`architecture.md:70`)なので `uint8 = round(clip(v,0,1)*255)`。

#### 2.4.4 マスク提案と正規化(決定性の分離点)【BL-8 反映】

- `Sam2MaskProposer`(`sam2_masks.py`): `SAM2AutomaticMaskGenerator` をラップ。
  - モデル既定 `model_id = "facebook/sam2-hiera-tiny"`(【実測】HF から認証不要 DL・14.8 秒 — `technique-ml-part-segmentation.md:130`)。
  - 既定 `points_per_side=16`(【実測】1.09 秒 — 同:132)。`pred_iou_thresh` / `stability_score_thresh` / `min_mask_region_area` を kwargs で透過。
  - デバイス: `torch.cuda.is_available()` なら `cuda`、でなければ `cpu` + **所要時間の警告**。
  - **`K` の上限ガード【NB 反映】**: `K > max_masks_per_view`(既定 512)は `ValueError`(`min_mask_region_area` を上げるよう誘導)。
- **テスト用スタブ**: `_StaticMaskProposer`(固定マスクを返す。`K=0` も可)と `_StaticRenderer`(合成 `RenderedView` を返す)をテスト側に置く。これで `MultiViewSegmenter.segment()` 全体を GPU 無しで厳密ゲートにかけられる。
- **マスク正規化(`fusion.py` 入口・決定性の要)**:
  1. 空マスク(True が 0 画素)を除去。
  2. 完全一致マスクを重複除去。
  3. **全順序キー**で昇順ソート: `(-pixel_count, first_true_flat_index, np.packbits(mask.ravel()).tobytes())`。
     - **WHY 第3キー【BL-8】**: `(-count, first_index)` の2キーは全順序でない(反例: 8×8 上の `{(0,0),(0,1)}` と `{(0,0),(0,2)}` はどちらも `(-2, 0)`)。安定ソートは入力順を保存するので、逆順入力で結果が変わる。内容ベースのバイト列を第3キーに置くことで全順序になる。
  - この時点から下流はマスク**内容**だけに依存する。
  - **ゲート fixture には「同画素数・同 first index の非同一マスク対」を必ず含める**(含まない fixture では順序不変性ゲートが偽の安心を与える)。

#### 2.4.5 視点間融合(`fusion.py`、決定的・本計画の最大の技術的難所)【BL-2 で設計変更】

**段階 A — 視点内の面割当**(視点 v ごとに `(M,) int32` を作る):

1. マスクを画素単位の単一ラベル図 `seg (H,W) int32`(-1 = どのマスクにも属さない)に畳む。**重なりの解決規約: 面積の大きいマスクから順に描き込み、小さい(=細かい)マスクが上書きする。**
   - WHY: SAM2 の自動マスクは入れ子(全身/胴/腕)になり得る。細かい方を採るのが「部位」の意図に近い。
   - **`seg` は int32**(int16 だと K 上限が暗黙になる)【NB 反映】。
2. 面 f の**可視画素**(`coverage & (face_id == f)`)上での `seg` の**最頻値**を求める。
   - **`seg == -1` も候補に含める**【NB 反映】。**WHY**: 除外すると、面の 90% がどのマスクにも属さないのに残り 10% の細片マスクが勝ってしまう。含めれば `assign_ratio` の分母が「可視画素数」になり定義が一貫する。
   - **数値契約(NEP 50 対応)**: 背景画素を先に除外(`valid = coverage & (face_id >= 0)`)したうえで
     `key = face_id[valid].astype(np.int64) * np.int64(K + 1) + (seg[valid].astype(np.int64) + 1)`
     → `np.unique(key, return_counts=True)` → `np.lexsort` で `(face, -count, seg)` 順に整列し先頭を採る。**O(H·W) メモリ・決定的・tie は小さい `seg` 優先。**
3. 最頻値が `-1` でなく、かつ `count / pix(v,f) >= assign_ratio`(既定 0.5)のときだけ割当。満たさない/不可視なら `-1`。
4. `view_segment[v] (M,) int32` に格納(値は**その視点内でのみ**意味を持つ)。

**段階 B — 辺の統計**(weld 面隣接の各辺 `(a,b)`、`E` 本):
```
both_v  = (view_segment[v,a] >= 0) & (view_segment[v,b] >= 0)
agree_v = both_v & (view_segment[v,a] == view_segment[v,b])
votes = Σ_v both_v        agree = Σ_v agree_v
w = agree / votes                                  (votes >= min_votes のときのみ定義)
prior(a,b) = True if 二面角(a,b) <= angle_deg else False
```
- **`min_votes` の既定は 2**【NB 反映】。**WHY**: 1 視点でしか観測されない辺は `w ∈ {0,1}` の二値になり、その 1 視点が誤れば確定してしまう。既定 2 なら 1 票の辺は「未観測」としてパス2(幾何プライア)へ回る。

**段階 C — 2パス union【BL-2 で全面改稿】**

> **v3 の欠陥(Codex 指摘)**: 意味境界の一部の辺で票が割れてカットしても、同じ境界上の**別の未観測辺**に `w=1.0` の幾何プライアが入ると橋になって両部位が再結合する。union-find は橋が 1 本でも残れば他のカットが全部無効になる。「観測箇所は ML・未観測箇所だけ幾何へ劣化」という設計意図が**部分遮蔽で成立しない**。

- **観測辺** = `votes >= min_votes` の辺。**観測面** = 観測辺を 1 本以上持つ面。
- **パス1(観測パス)**: **観測辺のみ**を対象に、`w >= merge_threshold`(既定 0.5)の辺を union する。
  - `w < merge_threshold` の観測辺は **カット確定**。以後どのパスでも復活しない。
  - パス1 後、各成分に「観測成分か否か」(観測面を 1 つでも含むか)を記録する。
- **パス2(未観測面の吸収)**: 未観測辺(`votes < min_votes`)は **2 つの確定済み観測成分を橋渡しできない**。次の3手順(**順序非依存・決定的**):
  1. **未観測成分どうしの結合**: 両端がともに未観測面である辺のうち `prior == True` のものを union(単純な連結成分 — 走査順に依存しない)。
  2. **吸収**: 各未観測成分について、隣接する観測成分ごとに「`prior == True` の境界辺の本数」を数え、**最大の観測成分へ吸収**(union)。tie は**最小の観測成分代表 index**。吸収は**パス1後の状態から一括で計算**する(逐次 union の順序依存を作らない)。
  3. **残置**: どの観測成分とも `prior == True` の辺で繋がらない未観測成分は、**独立した部位としてそのまま残す**(孤立シェル等)。
- **性質**:
  - **全辺が未観測(SAM2 が何も返さない/全面不可視)のとき** → パス1 は無操作、パス2-1 が幾何プライアの連結成分そのもの → **`DihedralSegmenter` と厳密一致**(ゲート7 維持)。
  - **観測済みの分割は未観測辺に潰されない**(BL-2 の新ゲートで反証済み)。

**段階 D** — 小部位マージ(`labels.py`、v2 §2.1 手順4 と**同一実装を共有**)。
**段階 E** — 正規化 relabel(`labels.py`、v2 §2.1 手順5 と**同一実装を共有**)。

**却下案(記録)**:
- **面ペア共出現行列 + スペクトラルクラスタリング** — `O(M²)` メモリ、クラスタ数の事前指定、固有ソルバが非決定的(符号・縮退固有値)。決定性の分離設計が壊れる。
- **視点ごとのラベルを直接多数決** — 視点間でマスク index に対応関係が無いため多数決できない(対応付けが別問題として発生)。辺の一致/不一致に落とすとこの問題が消える。
- **マスクの階層(入れ子)を明示的な木として使う** — SAM2 の自動マスクが厳密な木を成す保証がなく、木構築自体が追加ヒューリスティクスになる。段階 A-1 の「細かい方が勝つ」規約で必要十分。
- **v3 の1パス union(幾何プライアを常時混ぜる)** — 上記 BL-2 の理由で却下。

**初期パラメータ**(test-designer が **spike の実測を踏まえて**実装前に確定): `n_views=24` / `image_size=1024` / `projection`(spike で確定)/ `shading`(spike で確定)/ `points_per_side=16` / `assign_ratio=0.5` / **`min_votes=2`** / `merge_threshold=0.5` / `angle_deg=60.0` / `min_faces=None` / `visible_warn=0.95` / `assigned_warn=0.90` / `max_masks_per_view=512`。全パラメータに範囲検証(違反は `ValueError`)。

   → **Step 2-1.5 spike が唯一の解決手段**。ユーザーの実メッシュ待ち。不合格時の分岐は Step 2-1.5 に明記。
2. **`projection` / `shading` の既定値**(§2.4.1 / §2.4.3)。→ Step 2-1.5 spike で 2×3 の組合せを実測して確定。
3. **主 ML ゲートの閾値**(精度下限・`p_abs_max`・負の対照の Δ)。→ Step 2-1.5 spike の実測で test-designer が確定。
4. **`GL_DITHER` を moderngl API で無効化できるか。** → Step 2-3 probe (f)。できなければ GPU sentinel ゲートで不在を実証(§2.4.2)。sentinel が落ちたら R32UI 経路へ切替。
5. **moderngl の MRT + `fbo.clear()` の挙動。** → Step 2-3 probe (a)(b)(e)。破綻時は 2 パス方式へ切替(戻り契約不変)。
6. **`SAM2AutomaticMaskGenerator.from_pretrained` の有無 / Hydra グローバル状態の二重初期化。** → Step 2-5 probe (a)(b)。
7. **`uv lock` が `sam2`(sdist のみ)を Linux 向けにも解決できるか。** → Step 2-1 の合否条件。失敗なら承認事項 A2 の代替案へ。

9. **`atlas[p]` と `add_mesh` 順の対応**(v2 NB-1)。→ Step 2-6 probe (c)。
10. **`labels.py` の小部位マージが融合経路でも妥当か**(幾何用の規則を ML ラベルへ適用)。→ Step 2-4 のゲート 10 で挙動を固定。実アセット実測で見直す可能性あり。

12. **`capped_cylinder` の解析 UV とシーム帯分類の適合**(v2 BL-8)。→ test-designer が fixture 設計時に確定。
13. **`peanut_mesh` の最大二面角が `angle_deg=60` を下回るか**(P==1 の前提)。→ Step 2-4 のゲート 15 が**それ自体の検証**。落ちたら `n_theta` を増やす(閾値を緩めない)。
